# Octon Mini 4.1.0 to 4.2.0

This additive migration advertises governed autonomous delivery without
activating it.

The reviewed upgrade adds:

- the dormant `octon delivery` surface;
- strict autonomous-delivery schemas;
- locally bundled, inert autonomous-delivery and long-running-work payloads;
- project contract `harness.project.v8` with
  `autonomous_delivery.status = available_not_activated`; and
- the unassessed `autonomous_delivery` package trigger.

The migration does not:

- install or activate either package;
- select a delivery profile;
- generate a project decision, repository/provider fact, credential,
  confirmation, or standing authorization;
- execute a project hook;
- perform a network request or external effect; or
- renew or broaden an existing authorization.

Existing project-owned instructions, tasks, decisions, evidence, package
state, and modified files remain proposal-bound review items. Automatic work
is limited to safe additions, exact-pristine implementation successors, and
derived regeneration. Apply remains a staged, digest-bound transaction with
exact rollback evidence.

After upgrade, `./octon delivery status`, `research`, `context`, `assess`,
`plan`, `explain`, and `activation-preview` are read-only. Write-capable work
remains locked until an independently confirmed exact standing-authorization
record is activated.
