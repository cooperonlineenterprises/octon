# Disposable authorization-admission qualification

This source-only facet evolves the existing standing-delivery authorization
concern, reusing the unchanged intent/delegation shadow evaluator. The current
invocation explicitly permits bounded disposable operations. Synthetic issuer,
actor, intent, delegation, controls, obligations and accounting observations are
fixture inputs. This implementation issues no real grant and supplies no live
operational authority. No source DEC is allocated or adopted by qualification.

The source profile manifest remains the inventory owner with unchanged v3 rules.
Its disposable qualifier alone may select the separately versioned
`shared/source-contracts/admission-fixture-inventory.json` facet. Ordinary target
generation remains inactive. The facet pins every additional source-to-target
asset and only its experimental installation requires OpenSSL Ed25519 alongside
Python 3.11 and the canonical minimal core. Basic legacy inspection has no new
crypto dependency. No optional package is installed or made mandatory.

create TASK-0001 through the existing v1 task owner under the invocation's bounded
fixture authority, then copy only that synthetic task and focus into a fresh v2
fixture before qualification. IDs and task meanings stay intact; this is not a
supported live adoption or permission conversion. Historical schemas/readers and
foundation v1/v2 bytes are retained. Decision IDs and reserved ranges do not change.

## Contract and trust boundary

The fixture harness starts a separate controller process from copied runtime
assets with no source or sibling imports. OpenSSL Ed25519 creates ephemeral,
non-production issuer and actor keys. The issuer private key exists only in the
controller's temporary scope; the producer receives its public anchor. The actor
owns a separate ephemeral key. Neither private key enters templates, commits,
reports or logs; normal process cleanup removes temporary key files. These files
are not persistent credentials. Abrupt machine/process kill cleanup and secure
memory erasure remain unqualified.

The authorized harness supplies the issuer anchor and exact actor enrollment
outside the target. A producer signs each exact request with its actor key. The
controller verifies possession and enrollment, rejects repeated nonces, reads its
current in-memory control snapshot and signs the response with its issuer key.
The producer verifies that pinned key, fresh nonce, exact request digest and a
signed decision expiry bounded by ten seconds and every applicable validity/
freshness endpoint. Original intent and delegation references remain bound;
control updates cannot silently replace or renew their bytes.
Signing a statement proves its issuing key, not real principal enrollment, intent
fidelity, genuine qualified-human evidence, or operational permission.

The bound subject includes the canonical full plan bytes/digest, source revision,
installation digest, actual task bytes, root identity, work.handoff action,
expected prestate, policy bytes, governing synthetic intent and issuer, exact
before/after transaction lineage and allowed phase. The controller's updates are
on a separate parent control pipe. A cached signed response cannot answer a fresh
nonce or override current expiry, epoch, revocation or stop. The unchanged shadow
result always says execution authority is false. Only this invocation and the
explicit qualification context allow the one fixture transition.

Coverage retains parent/child issuer links, narrowing of every scope, duration,
limits, obligations and reservations, half-open validity, revocation, stop,
currentness, exact-action evidence and known coherent usage observations.
Missing required accounting/obligations refuse or remain indeterminate. No live
accounting ledger, budget reservation, grant store or new orchestrator is created.
Accounting is synthetic snapshot qualification; shared-budget races and billing
coverage are not established.

## Existing operation owner and recovery

Only the existing local `work.handoff` transaction is admitted. Its copied
transaction owner enforces exact operations, immutable verifier/control baselines,
unchanged instructions, exact shell-free validation commands, preconditions,
paths, content pre/postimages and receipt identity. Direct apply/recovery APIs
receive the same guard. Each live effect, validation boundary, receipt write,
rollback and implicit exception restore rechecks current fixture authority.

V2 fixture refresh uses an explicit per-action time/seed bound in the authenticated
subject to make staged derived bytes reproducible. V1 refresh is unchanged. These render inputs cannot freeze authority evaluation or
effect-time expiry; those use the current controller/host clock. This
allows the current controller and operation owner to bind exact derived postimages
and original recovery preimages rather than accepting arbitrary caller outcomes.

A durable pending journal marks an attempted transaction; a persisted exact
receipt confirms its local effect. Interrupted pre-effect and post-effect/pre-
receipt cases reconcile exact before/after states through the original transaction
owner. Divergence and forged path/preimage/directory/receipt lineage refuse.
Recovery uses a fresh current decision for the original exact footprint. An expired,
revoked or stopped fixture cannot silently restore old authority. If automatic
restore is refused, the journal and actual effects remain, and the refusal reports
that reconciliation is required. Fresh recovery/rollback/restore decisions are also retained as immutable
`octon.fixture-transaction-authority-observation.v1` evidence beneath the existing
transaction owner, content-addressed and linked to the original receipt/lineage.
These observations prove admission, not confirmed effects; the original operation
receipt/journal owns outcome truth. Inspection checks their structure and content
address; guarded operations verify their signatures and exact subject through the
trusted ephemeral anchor before obtaining another current decision. No authority
is reconstructed from them. A terminal recovered/applied/rolled-back identity
refuses replay before effects. New-issuer restart recovery is unsupported.

Signed fixture decisions are retained and verified through the existing receipt
validation evidence extension. Historical signatures do not supply current
permission; recovery independently obtains a fresh decision. Receipt/history
identity is preserved; no force
mode exists. Reconciliation precedes a new plan or retry.

The admitted transaction has no external effect route. Existing delivery adapter
fault fixtures separately exercise attempted, confirmed, known-failed and unknown
external outcomes with controlled subprocess/readback adapters and zero real
external effects. Those protocol tests do not establish external authorization
through this local admission path. Unknown outcomes have no automatic replay.

## Qualified properties and remaining enforcement gaps

Qualification covers actual copied runtime inspection, strict portable paths,
cryptographic issuer and actor possession, nonce-bound current-control responses,
parent narrowing, current local preconditions/validation baselines, exact handoff,
receipt preservation, interruption, current-authority recovery and rollback.
Native Windows execution is required in the candidate source matrix; Windows path
spelling alone is not that evidence. Producer path serialization uses explicit
POSIX conversion; readers retain strict rejection.

Separate same-UID processes and temporary files qualify protocol/key flow only.
They do not prevent a malicious worker from editing the external context, reading
another process's key files/memory, replacing an anchor/controller, killing a
process, controlling executable resolution or replacing the complete verifier
baseline. Native host sandbox/ACL isolation, protected clock/control enrollment,
process containment, power-loss durability, atomic control-to-write fencing and
real provider authorization remain unqualified. There is a check-to-write race
without such enforcement. The native host sandbox probe was unavailable in the
current managed environment; no hosted/host controls are changed to compensate.
Consequential/live execution therefore remains disabled.

This is one bounded IMP-1/IMP-2 bridge. It is not complete IMP-1/IMP-2, a released
runtime, live grant adoption, multi-run coordination, ChangeSets, consumer
migration or autonomous source integration. A future live successor still needs
properly authorized enrollment/activation, protected issuer/control/verifier and
worker boundaries, accounting/reservation ownership, exact consumer conversion,
and consequence-specific host/provider qualification. Qualified-human obligations
and principal intervention rights remain unchanged.
